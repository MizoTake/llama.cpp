# P100優先の通常構成でのRAMキャッシュ比較

2026-10-11、UnslothDesktopとLM StudioがロードしたP100優先の両GPU構成で、RAMキャッシュ無効と上限8,192 MiBを比較しました。モデルのGGUFファイル、GPU層数、デバイス、3:2のlayer split、F16 KV、チェックポイント32、各モデルの通常コンテキストをOFF/ON間で一致させています。

入力A、先頭から異なる入力B、元のA、同じAの順に処理しました。両設定の全32応答で期待回答42/84、出力SHA-256、終了理由stopが一致しました。別の入力を挟んだAで、RAM有効時のcache_n増加とprompt_n減少を確認しています。

以前のRTX退避構成の入力は4,846トークン（参照256行）でした。今回はモデル常駐中の冷却条件に合わせて入力を短くしています。OFF/ONの入力長は各ペアで同じですが、RTX測定との速度比較や、P100で4,846トークンを処理する長文性能の証拠には使いません。

## 再測定と根拠

各入力ファイルは `outputs/ram-cache/primary-{unsloth|lmstudio}-{9b|27b}-{0|8192}-short.json` です。全8ファイルのケース数・順序、実プロセスの設定、出力、熱制限、キャッシュ再利用を検証し、集計値と元ファイルのSHA-256を [JSON](ram-cache-primary-2026-10-11.json) に保存しました。キャッシュの導入とRTX退避構成の比較は [適用記録](ram-cache-2026-10-11.md) を参照してください。

測定は `scripts/p100/benchmark_ram_cache.py --gpu-profile primary --cache-mib 0|8192 --checkpoints 32`（Unsloth）を使います。LM Studioは通常プロファイルのチェックポイント32を使います。`--reference-rows`、モデル、回数は上表と各JSONの値を使い、実行中の生成終了を確認して共通サービスを停止した検証時間にのみ実行します。

今回の追加パラメーターは `--reference-rows 16 --rounds 1 --cool-temperature 77 --cooldown-timeout 1800` です。`--initial-cool-temperature` は9Bで69、27Bで67を指定しました。既定の各入力前の冷却目標は69Cなので、今回の再測定では77Cを明示します。出力先はOFF/ONで分けてください。

## 検証後の運用復帰

P100通常構成の追加測定後、2026-10-11T05:18:13.444714+00:00に共通サービスPID 47628、温度監視子PID 47984の生存とAPI状態 `matched-fallback` を確認しました。検証前に選択されていた `qwen/qwen3.5-9b` へ戻し、実プロセスのRAM 8 GiB、チェックポイント32、F16 KVを再照合しました。Unslothの保存済み8設定と、配置した7補助ファイルのハッシュ一致も確認しました。保存設定の退避78C、復帰69C以下・安定120秒、共有メモリとバックグラウンド要約の有効設定を維持しています。これは再開状態と設定の確認であり、新しい要約完了の性能測定ではありません。詳細は [配置・API確認記録](ram-cache-live-2026-10-11.json) の `primary_validation_after_restore` を参照してください。
