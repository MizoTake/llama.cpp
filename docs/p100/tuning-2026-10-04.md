# 追加チューニングの測定記録

管理用レシピのコミット `03dcb5c0f` 後に、最初の配布物の `llama-bench` を使って測定しました。実行ファイルのソースコミットは `11fe02151f79c41d0d4af7da708755d73b9c0da6`、モデルはQwen3.5-9B-Q4_K_Mです。

## CPUスレッド数

P100:RTX 4070 = 3:2、layer split、GPU offload 99、Flash Attention on、F16 KV、batch 512、ubatch 128、プロンプト512、生成128、各3回で測定しました。モデルと量子化・KV型は変更していません。

| CPUスレッド | プロンプト tokens/s | 生成 tokens/s | 生成の標準偏差 |
| ---: | ---: | ---: | ---: |
| 1 | 593.14 | 45.13 | 0.13 |
| 2 | 605.94 | 45.56 | 0.01 |
| 4 | 619.96 | 45.58 | 0.01 |
| 6 | 622.33 | 45.58 | 0.06 |

生成速度の差は小さいため、この結果で既定の6スレッドを変更しません。前回はプロンプト128・生成32だったので、その結果と速度向上率を計算することもできません。llama-benchにはトークナイズやサンプリング時間が含まれません。

測定を再現する例です。GPU番号を検出する既存の起動スクリプトを利用し、`MODEL.gguf` と配布物の場所を指定します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\p100\run-llama-p100.ps1 -BinaryDir "RUNTIME_DIRECTORY" -Tool bench -m "MODEL.gguf" -p 512 -n 128 -r 3 -t 1,2,4,6 -b 512 -ub 128 -ngl 99 -fa on -ctk f16 -ctv f16 -o json
```

## 持続負荷での制約

続けて配分6:5、4:3、3:2とubatch 128、256、512の組み合わせを測定した際、P100が79-81 C、SMクロックが405-417 MHzとなり、生成速度も大きく低下しました。P100のApplications Clocksは1189 MHz、最大SMクロックは1328 MHzでした。

最初の取得時点では温度制限のフラグは無効でした。その後、2026-10-04 12:11:22 JSTの `nvidia-smi -i 1 -q -d PERFORMANCE` で `SW Thermal Slowdown: Active` を確認しました。HW Thermal Slowdownの累積カウンターも、12:08:48の2246382 usから3863809 usへ増加しています。

温度制限が比較条件へ影響するため、この配分・バッチのスイープは途中で停止し、最速設定の選定には使いません。P100優先の3:2配分と既存の実行設定を維持しました。GPUの電力制限、クロック設定、温度保護は変更していません。

P100 PCIeはシステムからの送風を必要とするパッシブ冷却のカードです。[NVIDIA仕様書](https://images.nvidia.com/content/grid/pdf/DA-09018-001_v07.pdf)

次の比較では冷却・通風を確認し、各測定の温度、クロック、温度制限フラグを記録します。制限の出ていない同条件で、P100への配分を過半数に保ったGPU配分、batch/ubatch、Flash Attention、長いコンテキストを比較します。改善を採用する前に、使うモデルのUnslothバックエンドと実際のチャットでも確認します。

生ログはGit管理外の `build-p100-rtx4070/logs/` にあります。

- `tune-threads-9b.json`: 完了したスレッド数比較。
- `tune-split-ubatch-9b.json`: 中止した測定の途中出力。完全なJSONとは限りません。
- `tune-p100-low-clock.log`: 低クロック時の性能・温度・クロック情報。
- `tune-p100-after-stop.log`: 温度制限フラグを確認したログ。
